# 【指示】経費精算フォームのAI読み取りを直し、最新のGeminiモデルに切り替える

あなたはブラウザを操作できるエージェントです。以下の作業を順番に実行してください。
**「絶対に守ること」を必ず先に読んでから着手してください。**

---

## 絶対に守ること

1. **既存のデプロイURLを変えないこと。**
   このスクリプトはWebアプリとして公開されており、そのURLが
   GitHub Pages 上のフォーム（`index.html`）にハードコードされています。
   URLが変わると経費精算フォームが一切動かなくなります。
   - デプロイし直すときは「**デプロイを管理**」から**既存のデプロイを編集**して
     「**新しいバージョン**」を出すこと
   - 「**新しいデプロイ**」を作ってはいけない（URLが変わります）

2. **APIキーを報告文・チャット・コミットに絶対に貼らないこと。**
   キーの値を書き写してよいのは、Apps Script の
   「スクリプト プロパティ」の入力欄だけです。
   報告には「登録済み」とだけ書いてください。

3. **作業前に既存コードを全文コピーして保管すること。**
   何かあったときに戻せるようにするためです。コピーした全文は最後の報告に含めてください。
   （※ その全文に含まれる古いAPIキーの値は `AQ.****` のように伏せ字にしてください）

4. **指示にない箇所を書き換えないこと。**
   触るのは `analyzeReceipts` 関数と、キー定義の2行だけです。
   他の関数（`doPost`、`saveExpenses`、`getExpenses`、`deleteExpense`、
   `exportStaffPdfToDrive`、集計処理など）はそのまま残してください。

5. **判断に迷ったら止まって報告すること。**
   想定と違う画面・構造だった場合、勝手に解釈して進めず、
   画面の内容を報告して指示を仰いでください。

---

## 背景（なぜ直すのか）

経費精算フォームで領収書の写真を撮って「AIで一括読み取り」を押すと、
毎回このエラーが出ます。

```
解析エラー: 画像の解析に失敗しました: Geminiからの応答が空でした
```

原因は2つです。

**① APIキーの形式が違う**
現在 `Code.gs` に直書きされているキーは `AQ.` で始まる
**OAuthアクセストークン形式**です。Gemini API の `?key=` パラメータが
受け付けるのは、Google AI Studio が発行する
**`AIza` で始まるAPIキー**だけです。今のキーでは毎回 HTTP 400 が返ります。

**② エラーが握り潰されている**
`analyzeReceipts` は `muteHttpExceptions: true` で通信していながら
HTTPステータスを一度も確認していません。そのため Gemini が返した
`{"error":{"message":"API key not valid..."}}` という応答が
`candidates` を含まないことだけを見て、
「Geminiからの応答が空でした」という無関係なメッセージに化けていました。

**あわせて、使用モデルを現時点で最新のものに切り替えます。**

## 手順

### 手順1. 新しいAPIキーを発行する

1. https://aistudio.google.com/apikey を開く
2. Googleアカウントでログインする（このPCのアカウントでログイン済みのはず）
3. 「**APIキーを作成**」（Create API key）をクリック
4. プロジェクトを選ぶよう求められたら、既存のプロジェクトを選ぶ
5. 発行された `AIza` で始まるキーをコピーする
   - **キーの値はどこにも書き出さないこと。クリップボードに置いたまま手順3へ進む**
6. 一覧に古いキーが残っていて、明らかに使っていないものがあれば削除する
   - 判断がつかない場合は削除せず、一覧にあるキーの「名前と作成日」だけを報告する

> `AIza` で始まらないキーが表示された場合は、そこで止まって報告してください。

---

### 手順2. Apps Script を開く

1. https://script.google.com/home を開く
2. 経費精算のプロジェクト（名前に「経費」「精算」等を含むもの）を開く
   - 見つからない場合は、経費精算の集計スプレッドシートを開いて
     メニュー「**拡張機能**」→「**Apps Script**」から開く
3. `Code.gs` を開き、**全文をコピーして保管する**（絶対に守ること・3）

---

### 手順3. APIキーをスクリプトプロパティに登録する

1. 左メニューの歯車「**プロジェクトの設定**」を開く
2. 一番下の「**スクリプト プロパティ**」→「**スクリプト プロパティを追加**」
3. 次のとおり入力して保存する

   | プロパティ | 値 |
   |---|---|
   | `GEMINI_API_KEY` | 手順1でコピーした `AIza...` のキー |

4. 保存できたことを確認する（**値は報告に書かない**）

---

### 手順4. 新しいコードを追加する

1. 左メニューの「**ファイル**」の「＋」→「**スクリプト**」を選ぶ
2. ファイル名を `analyzeReceipts` にする
3. 別タブで次のURLを開き、表示されたコードを**全文コピーする**

   ```
   https://raw.githubusercontent.com/sakusakusansan-star/keihi23/claude/kore-ga-deruna-2ya4la/apps-script/analyze-receipts.gs
   ```

4. Apps Script に戻り、新しいファイルの中身を全部消して**全文貼り付ける**
5. 保存する（Ctrl+S）
6. 貼り付けたコードの先頭に `var GEMINI_MODELS = ...` の行があることを確認する
   （途中で切れて貼られていないかの確認）

---

### 手順5. 古いコードを削除する

**ここは必ず実施してください。** Apps Script は全ファイルが同じ名前空間を
共有するため、同名の `analyzeReceipts` が2つあるとどちらが使われるか不定になります。

`Code.gs` から次の3か所を削除します。

1. ファイル冒頭の**2行**
   ```js
   var GEMINI_API_KEY = "AQ.（略）";
   var GEMINI_API_URL = "https://generativelanguage.googleapis.com/...";
   ```

2. `// ── 画像(base64)をGeminiに渡して複数領収書を抽出 ─────────` の
   コメント行から始まる **`function analyzeReceipts(base64Image, mimeType) { ... }` の全体**
   （`throw new Error("画像の解析に失敗しました: " + e.message);` を含む `}` の閉じまで）

3. 保存する（Ctrl+S）

**削除してはいけないもの:**
`doPost` の中にある
```js
} else if (action === 'analyzeReceipts') {
  data = analyzeReceipts(req.base64Image, req.mimeType);
```
この呼び出しは**そのまま残してください**。新しいファイルの同名関数が使われます。

---

### 手順6. キーが有効か確認し、利用できるモデル一覧を取得する

1. エディタ上部の実行する関数のプルダウンから **`listGeminiModels`** を選ぶ
2. 「**実行**」を押す
3. 初回は権限の承認を求められる → 自分のアカウントで承認する
   （「このアプリは確認されていません」と出たら「詳細」→「（安全ではないページ）に移動」）
4. 「**実行ログ**」に出た内容を**全文コピーして報告に含める**

期待する出力:
```
✅ APIキーは有効です
generateContent が使えるモデル: NN件
----------------------------------------
gemini-2.5-flash   （…）
gemini-flash-latest   （…）
（以下、利用可能なモデルIDが並ぶ）
----------------------------------------
```

`❌ APIキーが無効です` と出た場合は、**そこで止まって**
ログのエラーメッセージを報告してください。

---

### 手順7. 使用モデルを最新のものに設定する

手順6で出た一覧から、次のルールで**1つだけ**選びます。

1. `gemini-flash-latest` があれば、**それを選ぶ**
   （常に最新のflash系を指すエイリアスなので、以後の乗り換えが不要）
2. 無ければ、**バージョン番号が最も大きい flash 系の安定版**を選ぶ
   （例: `gemini-3-flash` と `gemini-2.5-flash` があれば前者）
3. 次の語を含むモデルは**選ばない**:
   `preview` / `exp` / `lite` / `tts` / `image` / `embedding` / `vision-only`
4. **1〜3で決まらない場合は、選ばずに一覧を報告して止まる**

選んだら、手順3と同じ「スクリプト プロパティ」に追加します。

| プロパティ | 値 |
|---|---|
| `GEMINI_MODEL` | 選んだモデルID（例: `gemini-flash-latest`） |

> モデルIDはコードを書き換えずにここで差し替えられます。
> `models/` の接頭辞は付けても付けなくても構いません。

---

### 手順8. 選んだモデルで実際に動くか確認する

1. 実行する関数のプルダウンから **`testGeminiModel`** を選ぶ
2. 「**実行**」を押す
3. 「実行ログ」を確認する

期待する出力:
```
テスト対象モデル: （手順7で選んだモデルID）
✅ 応答あり: OK
このモデルで領収書の読み取りが動く状態です。
```

`❌ 失敗:` と出た場合は、ログのエラーメッセージを報告し、
手順7のルール2で次点のモデルIDに変えて手順8をもう一度試してください。
2回失敗したら、**そこで止まって**報告してください。

### 手順9. デプロイする（URLを変えないこと）

1. 右上「**デプロイ**」→「**デプロイを管理**」
2. 一覧にある**既存のデプロイ**の右上の**鉛筆アイコン（編集）**を押す
3. 「バージョン」のプルダウンで「**新しいバージョン**」を選ぶ
4. 「**デプロイ**」を押す
5. 表示されたウェブアプリURLが、**編集前と同じであること**を確認する
   - 違っていたら、**そこで止まって**報告してください

> 「新しいデプロイ」ボタンは絶対に押さないでください。

---

### 手順10. 実際のフォームで動作確認する

1. https://sakusakusansan-star.github.io/keihi23/ を開く
2. スタッフを選ぶ（例: 福山）
3. 「📷 写真でAI読取」タブで、領収書の画像を1枚選ぶ
4. 「🤖 AIで一括読み取り」を押す
5. 結果を確認する
   - **成功**: 「読み取り結果」に日付・金額が入ったカードが出る
   - **失敗**: 赤いエラーカードが出る → **メッセージを全文報告する**
     （「Gemini APIエラー (HTTP 400): ...」のように、
     今回の修正で本当の原因が表示されるようになっています）

**注意: 動作確認で読み取った内容は送信しないでください。**
「選択した項目を一括送信」は押さず、✕ボタンで画像を消して終了してください。
実際のスプレッドシートにテストデータを書き込まないためです。
